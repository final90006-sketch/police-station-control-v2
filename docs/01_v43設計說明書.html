1. 系統概覽

本系統是派出所層級的綜合勤務管制與績效追蹤工具，以 Excel 工作簿型式提供，目標是讓基層員警可單機操作、長官可一目了然檢視全所管制狀態。

三大管制領域

  • 刑案管制：未破/已破未移送/竊盜/詐欺/發展中
  • 毒品調驗：列管人口與到驗管制
  • 交通績效：違規項目目標達成率

資料規模

  • 案件容量：500 列硬上限（規則 33 預警）
  • 毒調/交通/發展中容量：各 150 列
  • 共計 26,465 個公式、33 條自動檢核規則、6 個 Excel Table

2. 設計哲學

2.1 Single Source of Truth

所有刑案資料只在 案件資料庫 一張表編輯，其他分頁透過 INDEX/MATCH 公式自動同步。

2.2 公式驅動，非巨集

v43 是 macro-free Plan B。原 v42 巨集版維運成本過高（全國機關鎖巨集、需重簽 vbaProject），改用純公式達成同樣功能。

2.3 自動健檢

系統自帶 33 條檢核規則，使用者打開檔案自動掃描資料一致性、公式運作、設定完整性，分綠/橙/紅三色顯示。

2.4 多層級可見性

透過 outline 折疊讓長官一眼看 50 列、稽核人員可展開全部 500 列。列印區段化只印可見列。

2.5 中文 sidecar 強制規範

所有自動化腳本 (.ps1) 必須是純 ASCII，中文一律走 UTF-8 sidecar 載入。原因：PS5.1 以 ANSI 讀 .ps1 會毀中文字面值。這是本專案反覆踩過的關鍵雷。

6. 核心 KPI 公式

管制總覽分頁的核心 KPI 計算邏輯：

未破案件（管制總覽!B21）

=COUNTIF(Tbl案件[案件狀況],"未破")

已破獲未移送（管制總覽!H21）

=COUNTIF(Tbl案件[案件狀況],"已破未移送")

發展中案件（管制總覽!B26）

=COUNTA(Tbl發展中[編號])

交通取締（管制總覽!H26）

=COUNTA(Tbl交通[編號])

績效統計案件（管制總覽!K26）

=COUNTA(Tbl刑案[編號])

未破案件管制 KPI（範例）

  • 未破案件總數 = COUNTIFS(Tbl案件[案件狀況],"未破",Tbl案件[發生管轄],"本轄")
  • 已破未移送 = COUNTIF(Tbl案件[案件狀況],"已破未移送")
  • 逾 30 日未破 = SUMPRODUCT((Tbl案件[案件狀況]="未破")*(Tbl案件[發生管轄]="本轄")*(TODAY()-Tbl案件[發生時間]>30))
  • 本週新增未破 = SUMPRODUCT((Tbl案件[案件狀況]="未破")*(Tbl案件[發生管轄]="本轄")*(TODAY()-Tbl案件[建立時間]<=7))

9. 系統檢核 33 條規則

使用者打開檔案，系統檢核分頁自動跑這 33 條規則，分四大類：

  • 系統完整性：核心物件是否存在（規則 01-08）
  • 資料一致性：欄位邏輯是否矛盾（規則 09-16、32）
  • 公式運作：KPI 是否正常輸出（規則 17-22）
  • 設定表內容：基本設定是否完整（規則 23-27）
  • 設計人保護：版本與啟用日期（規則 28-31）
  • 容量管理：資料量逼近上限預警（規則 33）
#類別檢核項目公式說明
01系統完整性案件資料庫表是否存在 =IF(ISERROR(INDIRECT("案件資料庫!A1")),"✗ 失敗","✓ 通過") 系統開檔即檢測
02系統完整性設定表是否存在 =IF(ISERROR(INDIRECT("設定表!A1")),"✗ 失敗","✓ 通過") 設定表是核心配置
03系統完整性員警姓名清單 Named Range 是否完整 =IF(ISERROR(COUNTA(員警姓名清單)),"✗ 失敗",IF(COUNTA(員警姓名清單)<5,"⚠ 警告","✓ 通過")) 至少要有 5 位員警
04系統完整性案類清單 Named Range 是否完整 =IF(ISERROR(COUNTA(案類清單)),"✗ 失敗",IF(COUNTA(案類清單)<10,"⚠ 警告","✓ 通過")) 至少要有 10 個案類
05系統完整性違規項目清單是否完整 =IF(ISERROR(COUNTA(違規項目清單)),"✗ 失敗",IF(COUNTA(違規項目清單)<8,"⚠ 警告","✓ 通過")) 至少要有 8 項違規
06系統完整性刑案案類清單是否完整 =IF(ISERROR(COUNTA(刑案案類清單)),"✗ 失敗",IF(COUNTA(刑案案類清單)<10,"⚠ 警告","✓ 通過")) 至少要有 10 個刑案案類
07系統完整性Tbl案件 Excel Table 是否完整 =IF(COUNTA(案件資料庫!$B$13:$Y$13)>=18,"✓ 通過","✗ 失敗") 案件資料庫表頭應有 18 欄以上
08系統完整性工作表數量是否正確 =IF(COUNTA(設定表!$C$15)=1,"✓ 通過","⚠ 警告") 派出所名稱必須存在
09資料一致性案件編號是否有重複 =IF(SUMPRODUCT((COUNTIF(Tbl案件[編號],Tbl案件[編號])>1)*(Tbl案件[編號]<>""))>0,"✗ 失敗","✓ 通過") 編號是案件主鍵不可重複
10資料一致性未破案件是否有破獲時間 =IF(SUMPRODUCT((Tbl案件[案件狀況]="未破")*(Tbl案件[破獲時間]<>""))>0,"⚠ 警告","✓ 通過") 未破案件不應有破獲時間
11資料一致性已破案件是否有破獲時間 =IF(SUMPRODUCT((Tbl案件[偵辦進度]="已破獲")*(Tbl案件[破獲時間]=""))>0,"⚠ 警告","✓ 通過") 已破獲應記錄破獲時間
12資料一致性本轄案件是否漏記發生時間 =IF(SUMPRODUCT((Tbl案件[發生管轄]="本轄")*(Tbl案件[發生時間]=""))>0,"⚠ 警告","✓ 通過") 本轄發生案件必填發生時間
13資料一致性案件是否漏填承辦人 =IF(SUMPRODUCT((Tbl案件[編號]<>"")*(Tbl案件[承辦人]=""))>0,"⚠ 警告","✓ 通過") 每案應指定承辦人
14資料一致性案件是否漏填案類 =IF(SUMPRODUCT((Tbl案件[編號]<>"")*(Tbl案件[案類]=""))>0,"✗ 失敗","✓ 通過") 案類為必填欄位

10. 工作流程（案件生命週期）

10.1 新增案件

  1. 使用者打開「案件資料庫」分頁（密碼 KD2026 解鎖）
  2. 在 Tbl案件 第一筆空白列填入 14 個欄位（必填 9 欄、選填 5 欄）
  3. 使用下拉選單選擇：案類、案件狀況、偵辦進度、發生/查獲管轄、承辦人
  4. 填入發生時間、案情摘要、發生地點等文字欄位
  5. 計算欄（R:Y 鎖定）自動產生「是否破獲、歸屬年度、未破排序、竊盜排序…」等
  6. 所有相關管制表（未破/竊盜/詐欺/管制總覽）即時更新
注意：「案件輸入」分頁雖有表單外觀，但 v43 無巨集後無「寫入資料庫」按鈕，實際輸入請至「案件資料庫」。

10.2 案件狀態轉換

新增   →  未破        ←─┐
         ↓               │（偵辦中）
       已破獲           │
         ↓               │
       已破未移送  ──────┘
         ↓
       已移送
         ↓
       簽結（結案）

10.3 月份結算（手動，規則 31 永遠 WARN 提醒）

  1. 每月底打開「歷史資料」分頁
  2. 看 R140 列「本月即時 KPI」（公式自動算出當月數字）
  3. 選取該列 C:N → 複製
  4. 在最上方資料列（R16）按右鍵「插入列」
  5. 新列上「選擇性貼上 → 值」（凍結成快照，不再隨資料變動）
  6. B 欄填統計年月（民國年/月，如 115/05）、O 欄填備註

10.4 案件量逼近 500 列

  1. 規則 33 預警觸發（≥ 487 列）
  2. 判斷哪些舊案可歸檔（已結案/簽結超過 6 個月）
  3. 把這些舊案從 Tbl案件 中刪除（也可備份到外部）
  4. 系統繼續執行

13. 重做建議

若您要從零重做（不論是 Excel 重寫、Web App、Access），請保留以下核心設計，並考慮以下改善方向：

13.1 一定要保留的設計

✓ Single Source of Truth

案件只在一張表編輯，所有 view 自動同步。這是系統一致性的基石。

✓ 33 條自動檢核

每次打開檔案就驗證資料一致性，比事後抽查可靠百倍。

✓ 多層級可見性

長官看 50 列、稽核展開全部。outline 機制有效。

✓ 公開版 / 內部版分離

內部含真名、公開版完全去識別化。建議自動化 sanitization pipeline。

13.2 可改善的方向

⚠ 案件輸入分頁

v43 後完全無作用，應該：① 改成「預覽列 + 貼上工作流」② 或徹底刪除、改在資料庫直接編輯

⚠ KPI Dashboard 與資料欄寬綁定

3 大管制表的 KPI 卡片用同樣欄位，導致卡片寬度被資料欄拖累。建議 KPI 用獨立列高 + 文字塊（不依欄位寬度）。

⚠ 月快照手動流程

沒有巨集就只能手動。若改成 Web 版可自動化此流程。

⚠ 多人共用

Excel 檔案是單機型，多派出所需要分別維護。若改 Web App 可中央集權。

13.3 如果改成 Web App

  • 技術選擇：前端 vanilla JS + 後端 Node.js / Python FastAPI + 資料庫 SQLite/PostgreSQL
  • 資料模型：照本說明書的 6 個 Table 1:1 翻成資料庫 schema
  • 檢核規則：33 條規則改寫成後端 validation hooks 或前端 form 即時驗證
  • 列印：用 print CSS 或產生 PDF（puppeteer 或 weasyprint）
  • 權限：員警／所長／分局／縣府四層 RBAC
  • 離線：PWA + IndexedDB，斷網仍可登錄

13.4 如果留在 Excel 但重設計

  • 把 KPI Dashboard 抽到獨立分頁（不與資料表共用欄位）
  • 明確標示「案件輸入」表單不可用、引導去案件資料庫
  • 建立 case template snippet：使用者複製一列空白模板再貼到案件資料庫
  • 加上自動歸檔輔助：規則 33 觸發時，提示哪些案件可歸檔
